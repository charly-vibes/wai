# Format: <spec>/<scenario-id>   # <owning ticket(s)>
#
# Every scenario listed here is declared in openspec/specs but not yet
# verifiable: its contract stub carries an empty [tests] table
# (no-tests-declared) or no contract exists at all (no-toml). The corpus was
# authored under espectacular 0.2.2 with `authored_with = "0.1.0"` stubs and
# ah 0.12.2 requires declared tests, so these surfaced when the gate was first
# wired (wai-ycr5). They are real gaps, not formatting drift: no test verifies
# these scenarios. Pay them down scenario by scenario.
#
# The ratchet:
#   - allows exactly these no-toml / no-tests-declared findings
#   - fails on any other finding (orphan-toml, slug-collision, execution)
#   - fails when a scenario is NOT listed but lacks contract/tests (new
#     backlog must be declared with its ticket in the same change)
#   - fails when a listed scenario is now declared (stale line: prune it)
#
# The list only shrinks, except when a spec-first ticket adds a scenario and
# records it in the same change.
