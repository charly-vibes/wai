PLAN wai-vx02-5-inter-child-handoff. Desired behavior: when a child pipeline run under a beads epic records a handoff artifact (via 'wai handoff create' with the run active), the epic run tree marks that child handoff-ready and links the artifact path; when the next child starts, 'wai pipeline current' surfaces the prior child's handoff artifact path. Out of scope: LLM-summarized handoffs, cross-epic handoffs, auto-injection of artifact contents into prompts, changes to close enforcement. Test cases (tests/integration.rs, epic fixture style — fake-bin bd + hand-written run-state YAML): (1) epic_handoff_terminal_child_marks_handoff_ready — parent fixture + terminal child run fixture (current_step == total, handoff_artifact set) -> 'pipeline current --json' contains "handoff_ready": true and the artifact path; (2) epic_handoff_midflight_child_not_handoff_ready — mid-flight child (current_step 0) -> "handoff_ready": false; (3) epic_handoff_create_records_artifact_on_active_run — init, project, pipeline start --topic=child-a, 'wai handoff create my-app' -> child run state gains handoff_artifact pointing at the created handoff doc; (4) epic_handoff_next_child_surfaces_prior_sibling_handoff — parent + terminal child-run-a with artifact; 'pipeline start my-pipe --topic=child-b' then 'pipeline current --json' -> output names prior child's handoff artifact path (tree built via parent lookup from the child active run). Narrow: cargo test --test integration epic_handoff_ -- --nocapture. Full: cargo fmt && cargo clippy --all-targets -- -D warnings && cargo test. Files: src/commands/pipeline/mod.rs (PipelineRun.handoff_artifact), src/json.rs (ChildRunNode.handoff_ready/handoff_artifact), src/commands/pipeline/orchestration.rs (parent lookup + node fields, record_handoff_artifact), src/commands/handoff.rs (record path on active run), tests/integration.rs.
