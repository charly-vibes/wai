# RO5U review — wai-63h9 wait-primitive diff

Scope: src/pipeline_wait.rs, orchestration.rs wait section, CLI wiring, template edits (builtin + deployed fork), tests/suite_pipeline_wait.rs, Cargo.toml dep.
Passes: 1 structure, 2 correctness, 3 edge cases, 4 clarity, 5 production-readiness.

## Critical

1. **pipe-full deadlock** — `src/commands/pipeline/orchestration.rs` `cmd_wait`: stdout/stderr captured with `Stdio::piped()` but drained only AFTER `wait_timeout` returns (`read_pipe(child.stdout.take())` in the `Ok(Some(status))` arm). If gh's watch redraw output exceeds the OS pipe buffer (~64KB) before exit, gh blocks on write and never exits → wait_timeout spuriously exhausts the budget on long healthy watches; every long wait ends Timeout. **Fix:** take both handles before waiting, spawn two concurrent drain threads (`read_to_string` — blocks on EOF, no polling), join them after wait_timeout (kill closes pipes → drains terminate in the timeout branch too).

## High

2. **zero-checks misclassification order** — `classify_wait_exit` checks `code == Some(0)` BEFORE the "no checks" message; gh versions that exit 0 while printing "no checks reported" classify as `Passed{0,0}` instead of `ZeroChecks`. **Fix:** check combined output for "no checks" first, regardless of exit code.
3. **Passed{0,0} renders "all checks pass (0/0)"** when counts can't be parsed — misleading. **Fix:** when `total == 0`, omit the counts segment.

## Medium

4. **summary_line takes pr: u64** — branch-name PRs render as "PR 0". **Fix:** change signature to `pr: impl std::fmt::Display` (tests' integer literals still compile; branch names render verbatim).
5. **gh invocation/auth errors** (spawn ok, nonzero exit, stderr "gh: …") surface as "checks FAILED (0/0 passing)" — misleading but recoverable. **Fix deferred:** needs a new `WaitOutcome::Error` variant + test coverage; out of this slice's minimal footprint. Record as follow-up.

## Low

6. `validate_pr_arg` rejects branch names starting with '-' — rare; safe-side rejection, accepted.
7. `--timeout 0` = immediate timeout + requery; default 30 documented, no guard needed.
8. `emit_wait_outcome` uses `std::process::exit` (skips destructors) — intentional: the exit code is the primitive's script API; documented in the fn comment.

**Verdict:** fix Critical 1 + High 2/3 + Medium 4 in the fix step; Medium 5 deferred as follow-up; Lows accepted.
